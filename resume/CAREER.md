### 긴 버전 (자기소개서용) — "불편을 해결하는 개발자"
저는 어떠한 불편한 점이 생기면 해결할 방법이 없을지 고민합니다.

NFT 작가들의 불편함을 해결하고자 NFT 발행 플랫폼(크래프트맨쉽)을 개발해 운영했습니다.
평소 블록체인과 NFT에 관심이 있어 NFT 작가 커뮤니티에서 공부하던 중, 작가들이 개발 지식이
없어 컨트랙트 배포와 NFT 발행에 어려움을 겪는 것을 알게 되었습니다. 결과적으로 1,000개 이상의
컨트랙트 배포와 약 35,000개의 NFT 발행이 이루어졌습니다.

또한 교통카드의 불편함을 해결해 특허 등록에 성공한 적이 있습니다. RF-ID 교통카드가 모두 같은

카드 안의 안테나 역할을 하는 구리선을 ON/OFF 할 수 있어야 오류를 잡을 수 있다는 결론에
도달했습니다. 카드 자체에 클립 형식의 스위치를 추가해 사용자가 교통카드 기능을 ON/OFF

Block 누락이 발생하며 Rich List가 없었다.

**해결**: 모든 Block과 Transaction을 DB에 저장하는 방향으로 신규 구축.
**담당**: 백엔드의 블록 파싱 및 데이터 Summary 파트.
- Block / Transaction 구조를 파악하고 필요한 RPC 명령어 조사
- Java HttpClient + JPA로 `getblock`, `getblockhash`, `getrawtransaction` 결과를 DB화
- `@Scheduled`로 현재 블록 높이와 수집 중인 블록 높이를 비교해 지속적으로 파싱·저장
- 적재 데이터를 Summary 해 프론트에 제공

`Java 11 · Spring Boot 2 · Gradle · MySQL · JPA · AWS`

## 6. 강점 근거 — "안정에 만족하지 않는 팀원"

이력서 본문에는 안 넣지만 **면접에서 꺼낼 카드**. 운영 중인 서비스에 만족하지 않고 에러 여부와
고도화 여지를 먼저 찾아 제안한 사례들.

1. **코인 → 자체 포인트 전환 올림 이슈** (케이스타페이)
   전환 시 항상 올림 처리를 하고 있었는데 근거를 이해할 수 없었음. 지금까지 올림 처리된 포인트
   관련 서류와 수정이 필요한 부분을 정리해 팀장에게 제안 → 수정 작업 진행.

2. **텔레그램 모니터링 봇 제안** (케이스타페이)
   거래소 매수 API 서버 개발 당시, 사내에서 텔레그램을 많이 쓰는 점에 착안해 봇을 제안하고 개발.
   매수 연동 현황 · 가격 조회 · 가중치 변경을 관리자가 언제든 확인할 수 있게 함.

3. **Procedure 로직 오류 발견 — 천만 건 규모 영향** (옐로커머스)
   상품 정보 Insert/Update에 Procedure를 사용 중이었음. 공부 목적으로 로직을 보다가 특정 회사의
   update 로직에서 **update 날짜와 재고 개수 비교 조건이 반대로** 되어 있는 것을 발견.
   **약 천만 건 이상의 상품이 업데이트되지 않고 있었음.** 상황을 정리해 팀장에게 보고 후 오류 수정.

4. **Kafka 수집 시간 단축 제안 (미채택)** (옐로커머스)
   수집에 10시간 이상 소요돼 EP 파일을 나눠 멀티 Producer로 구성하자고 제안. EP 파일 정확 분할이
   불가하고 이미 Consumer가 15개 이상이라 현 시점에서는 불필요하다는 피드백을 받아 미진행.
   *(제안이 반려된 사례도 그대로 기록 — 판단 근거를 이해하고 수용한 과정 자체가 자료)*

5. **커뮤니티 기반 고도화** (크래프트맨쉽)
   NFT 발행 플랫폼 운영 시 커뮤니티를 함께 운영해 작가 니즈를 리스트업 → 전 NFT 정보 불러오기,
   런치패드 NFT 개수, 다양한 파일 포맷 지원 등 고도화 진행.
